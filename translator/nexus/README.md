# translator.nexus — автоматическая загрузка модов с Nexus

Модуль делает то же, что даунлоадер Nolvus, но с одним отличием, ради которого он и
написан: **на бесплатном аккаунте загрузка идёт без единого клика**. Пользователь один
раз входит в свой Nexus-аккаунт в видимом окне Chrome — дальше ни кнопки, ни ожидания,
ни участия.

## Две схемы подписи, а не одна

Ссылку на CDN подписывают двумя независимыми способами, и это главное, что нужно
понимать про весь модуль.

**`download_link.json`** (публичный API) подписывает парой `key`/`expires`:

```
GET /v1/games/{game}/mods/{id}/files.json                        → выбрать file_id
GET /v1/games/{game}/mods/{id}/files/{fid}/download_link.json    → [{name, short_name, URI}]
GET {URI}                                                         → байты
```

Голым его можно звать только с Premium-ключом; бесплатному прилетает `403`. Пару
`key`/`expires` Nexus подписывает в момент нажатия «Mod Manager Download», привязывает
к сессии и убивает через несколько минут. Эндпоинта, выдающего её по запросу, нет.

**`GenerateDownloadUrl`** (эндпоинт самого сайта) подписывает парой `md5`/`expires`:

```
POST /Core/Libs/Common/Managers/Downloads?GenerateDownloadUrl
     game_id=1704&fid=359894&collection_id=0
  → {"url": "https://supporter-files.nexus-cdn.com/1704/84988/...?md5=&expires=&user_id="}
```

Этот подписывает для **любой залогиненной сессии**, без Premium и без клика: ровно его
дёргает страница загрузки, когда пользователь жмёт кнопку. Измерено (2026-09): ссылка
живёт 14400 с, то есть 4 часа.

Разница между схемами — кто делает запрос, а не что получает. Поэтому бесплатный
аккаунт с залогиненным браузером качает так же непрерывно, как премиумный.

## Почему всё-таки браузер

`www.nexusmods.com` стоит за Cloudflare Bot Management. Обычный HTTP-клиент
отбивается на уровне TLS — измерено: `403 cf-mitigated: challenge`, одинаково с
Chrome-овским User-Agent и без него, потому что признак — это ClientHello, а не
заголовки. Вытащить куку из браузерного профиля не помогает: до куки дело не доходит.
Транспортом обязан быть браузер.

**Но не так, как у Nolvus.** Nolvus инжектит JS в свой встроенный CefSharp и кликает
`#slowDownloadButton` — поэтому и ломается на каждом редизайне страницы (в их текущем
скрипте уже прикручен запасной проход по shadow DOM; `Scripts/VectorDownload.js` на нём
и сломался). Здесь вместо клика по кнопке выполняется тот самый `fetch`, который делает
сама страница, в её же origin и с её же куками. Нет ни поиска по DOM, ни навигации по
странице мода, ни ожидания отсчёта: одна вкладка стоит открытой, и каждая ссылка — это
один запрос из неё.

Чего модуль **не** делает: не подделывает сессию, не обходит вход, не парсит страницу.
Вход выполняет человек, один раз, в окне, которое он видит.

## Слои

| Файл | Отвечает за |
|---|---|
| `client.py` | API v1: `files`, `file`, `download_link`, `md5_search`, `validate`. Ретраи, типизированные ошибки, парсинг квоты из `X-RL-*` |
| `resolver.py` | `mod_id` (+ подсказки) → один `file_id` |
| `providers.py` | откуда берётся CDN-ссылка: `Premium` / `Browser` / `Nxm` / `Chain` |
| `browser.py` | Chrome по DevTools Protocol: минт ссылок, вход, синхронный мост `BrowserSession` |
| `link_cache.py` | подписанные ссылки живут 4 часа — кеш на диске, чтобы не поднимать браузер зря |
| `search.py` | поиск модов через GraphQL v2: по словам, по подстроке, случайный, поиск переводов |
| `archive.py` | распаковка `.7z`/`.zip`/`.rar` через 7-Zip, с защитой от выхода за каталог |
| `harvest.py` | чтение строк: плагины, MCM (в т.ч. внутри BSA), SWF через FFDec |
| `merge.py` | сопоставление строк донора с нашими и запись результата |
| `translate_from_mod.py` | весь поток: найти → скачать → распаковать → сопоставить → применить → убрать |
| `downloader.py` | докачка по `Range`, перебор зеркал, проверка размера и MD5, атомарный `os.replace` |
| `manager.py` | очередь, пул потоков, машина состояний, снапшот для UI |

Всё, кроме `manager.py`, не хранит состояния.

## Выбор файла (`FileResolver.resolve`)

Подсказки по убыванию точности:

1. `file_id` — точное совпадение, список файлов даже не запрашивается
2. `file_name` — имя архива на диске; при переименовании подхватывается по
   `uploaded_timestamp`, зашитому в имя (`Name-84988-1-1-1676429990.7z`)
3. `version` — нормализуется, так что `v1.1`, `1-1` и `1.1.0` — одно и то же

Без подсказок вернётся самый свежий `MAIN`. **С подсказкой, которая ни к чему не
подошла, будет ошибка**, а не подстановка другого файла: модлист, запинивший v1.1 и
молча получивший v3.0, — это сломанная сборка, которая всплывёт через несколько часов
как CTD. Расширить поиск можно явно — `allow_newest=True`.

`ARCHIVED` и `OLD_VERSION` автоматически не выбираются никогда (только явным `file_id`).

## Загрузка

- **Докачка.** Пишем в `.part`; после обрыва следующая попытка запрашивает `Range`.
  Обрабатываются три реальных ответа зеркал: `206` (норма), `200` (зеркало
  проигнорировало `Range` — начинаем заново, а не дописываем вторую копию) и `416`
  (файл уже целиком скачан).
- **Перебор зеркал.** Мёртвое зеркало передаёт эстафету следующему, `.part` сохраняется.
- **Проверка.** Размер всегда, MD5 — если известен. Битый архив не переименовывается
  в финальное имя.
- **Пропуск.** Файл, уже лежащий на диске с верным размером/MD5, не качается повторно.

## Free-аккаунт, основной путь: минт через браузер

```
POST /api/nexus/downloads
  → resolve выбирает file_id
  → BrowserLinkProvider просит BrowserSession подписать ссылку
  → Chrome (уже запущен, уже залогинен) шлёт GenerateDownloadUrl из открытой вкладки
  → подписанный URL уходит в downloader — дальше всё как у премиума
```

Пользователь в этой схеме не участвует. Единственное ручное действие — вход, один раз
на профиль: `POST /api/nexus/browser/login` открывает окно и ждёт, пока в нём войдут.
Кука лежит в каталоге профиля и переживает перезапуски.

**Chrome закрывается корректно, а не убивается.** Куки живут в памяти, пока Chrome их
не закоммитит, а `Popen.terminate()` на Windows — это `TerminateProcess`: ни обработчиков
выхода, ни сброса на диск. Убитый так браузер теряет вход, и профиль, ради которого всё
затевалось, на следующем запуске оказывается пустым (измерено: сессия успела подписать
ссылку и исчезла после перезапуска). Поэтому `close()` сначала шлёт CDP `Browser.close`
и ждёт, и только потом достаёт `terminate`.

Темп запросов ограничен (`browser_mint_interval_sec`, по умолчанию 1.5 с + джиттер):
Nexus — общий сервис, а модлист — это тысячи файлов. Это не обход лимита, а вежливость.

Профиль — **отдельный**, а не пользовательский: Chrome отказывается отдавать
remote debugging на профиле по умолчанию, и заодно куки Skylator не мешаются с обычным
браузером пользователя.

**Путь к профилю всегда приводится к абсолютному.** Chrome разрешает `--user-data-dir`
относительно своего рабочего каталога, а не нашего, и, не сумев его открыть, он не
падает: он поднимает модальное окно «cannot read and write to its data directory» и
ждёт. Процесс жив, порт отладки не открыт, и с нашей стороны это выглядит как таймаут
подключения к живому браузеру — диагноз, который можно искать час. В `config.yaml` путь
разрешается относительно самого конфига, а не рабочего каталога, так что относительный
действительно доезжает.

## Что знает профиль, когда браузер выключен

Сессия лежит в каталоге профиля, а не в процессе, поэтому «залогинен ли» нельзя
проверить, не запустив Chrome, — а дашборд не должен поднимать браузер на каждый опрос.
Поэтому после подтверждённого входа рядом с профилем пишется `.skylator_session.json`:
имя, `memberId`, роли, срок жизни сессии.

| Поле | Значение |
|---|---|
| `logged_in` | проверено прямо сейчас; `null`, если Chrome не запущен |
| `last_session` | память о последнем входе — не проверка |
| `ready` | нужен ли человек: истинно и по живой проверке, и по непросроченной памяти |

Маркер с истёкшим сроком за готовность не считается: иначе UI сообщал бы, что всё в
порядке, ровно до того момента, когда упала бы целая пачка. Проверить наверняка —
`GET /api/nexus/browser?verify=1`: поднимает Chrome и спрашивает сессию по-настоящему.

Измеренная форма ответа `/api/auth/session` (2026-09):

```json
{"expires": "1792259208",
 "user": {"memberId": 1234567, "name": "someuser",
          "membershipRoles": ["member", "supporter"], "email": ""}}
```

`email` пуст даже у залогиненного аккаунта, так что признак входа — `memberId`/`name`.
Разлогиненному приходит литерал `null`, а не `{}` и не `401`. Сессия живёт около месяца:
именно это делает «войти один раз» правдой, а не лозунгом.

## Окно браузера: сколько раз вы его увидите

Не на каждый мод. `BrowserSession` — синглтон: Chrome поднимается при первой ссылке,
которой нет в кеше, и переиспользуется всеми последующими.

**Headless невозможен.** Измерено на профиле, который залогинен и работает: с
`--headless=new` страница — это интерстишл Cloudflare. Куки те же самые (`document.cookie`
отдаёт одинаковый набор в обоих режимах), но заголовок — «Just a moment...», в URL
появляется `__cf_chl_rt_tk`, а `/api/auth/session` отвечает `403 text/html` вместо
`200 application/json`. Это не проблема кук: бот-менеджмент просто не пускает headless,
и обходить это модуль не будет.

Поэтому окно настоящее, а его стоимость снижена тремя способами:

| Что | Как |
|---|---|
| `link_cache_path` | подписанная ссылка живёт 4 часа и кешируется на диск — повтор, пересабмит пачки и перезапуск процесса браузера не требуют вовсе |
| `browser_window_mode` | `minimized` (по умолчанию) сворачивает окно, `offscreen` уводит за пределы экрана, `normal` — как обычно |
| `browser_idle_close_sec` | Chrome закрывается, простояв без дела (по умолчанию 10 минут), и поднимается снова только когда понадобится |

**Состояние окна ставится по CDP, а не флагом запуска.** `STARTUPINFO.wShowWindow` здесь
не рычаг: он лишь подсказывает `nCmdShow` для первого `ShowWindow`, а Chrome его не
передаёт — окно он размещает сам, по своему профилю. Измерено: запуск с
`SW_SHOWMINNOACTIVE` даёт `visible=True, minimized=False, rect=(0,0,800,600)`, то есть
обычное видимое окно. Работает `Browser.setWindowBounds` после подключения:
`minimized=True`.

Запускается окно всё равно за пределами экрана — Chrome рисует первый кадр раньше, чем
к нему можно подключиться, и это как раз та вспышка, которую было бы видно. Windows
подрезает координату (`-32000` → `-16384`), но этого достаточно.

Перед запросом входа окно **возвращается на экран** (`show_window()`): просить войти в
окно, которого не видно, — хуже, чем не прятать его вовсе. После входа оно снова
сворачивается.

Измерено: холодный запуск — окно, 1.7 с на минт; повтор того же файла после перезапуска
процесса — **0.00 с и ни одного процесса Chrome**, ссылка из кеша скачивает файл (HTTP
200, верный размер).

Кеш лежит в `cache/` вместе с остальным локальным состоянием и в git не попадает:
ссылка несёт подпись, привязанную к аккаунту. Тот, кто может прочитать этот файл, и так
читает `config.yaml`.

## Free-аккаунт, запасной путь: handoff через nxm://

Остаётся как fallback — он не требует ни Chrome, ни сохранённой сессии, поэтому работает
там, где браузерный путь не поднять вообще.

```
POST /api/nexus/downloads
  → item переходит в waiting_link и отдаёт nexus_url
  → пользователь открывает страницу, жмёт «Mod Manager Download»
  → обработчик nxm:// делает POST /api/nexus/nxm {url}
  → NxmTicketStore будит нужный воркер, тот дёргает download_link с key/expires
  → дальше всё как у премиума
```

Билеты одноразовые (Nexus считает ключ израсходованным) и протухшие отбрасываются.

Браузер сервером **не открывается** по умолчанию (`nexus.nxm_open_browser: false`):
Flask часто крутится на headless- или удалённой машине. Локальному CLI флаг можно
включить.

## Кто кого ждёт: `interactive`

У каждого провайдера есть флаг `interactive` — нужен ли человек ради **этого конкретного
файла**. `Nxm` — да, `Premium` и `Browser` — нет. Менеджер читает флаг и решает,
сериализовать ли получение ссылок: просить три клика одновременно — плохо, а минтить
три ссылки одновременно — просто быстрее. Цепочка считается интерактивной, если
интерактивен хоть один её участник: решение принимается до того, как станет известно,
кто именно ответит.

Цепочка переходит к следующему провайдеру только на `LinkProviderUnavailable`
(«не мой случай»: нет Premium, нет сессии в браузере). `404` или сетевая ошибка — это
настоящая ошибка, и она всплывает: иначе пользователя отправят жать «Mod Manager
Download» на странице, где файла уже нет.

## Поиск: почему отдельный протокол

**В публичном API v1 поиска нет вообще.** Он умеет отдать мод, который вы уже можете
назвать по id, свежие загрузки, трендовые и `md5_search` — и это вся поверхность.
Поиск живёт в GraphQL по адресу `https://api.nexusmods.com/v2/graphql`: другой
протокол и другая схема, поэтому `search.py`, а не метод в `client.py`.

Схема снята интроспекцией самого эндпоинта (2026-09), и каждый запрос отсюда прогонялся
по живому сервису прежде, чем попасть в код. Эндпоинт отвечает и анонимно, но ключ
всё равно отправляется.

### Измеренные грабли

- Аргумент называется `count`, а не `limit`. На `limit` приходит явная ошибка.
- `name` + `WILDCARD` принимает **голую подстроку**: `"Ordinator"` — 266 модов,
  `"*Ordinator*"` — ноль. Обернуть в звёздочки — очевидная догадка, и она молча
  возвращает пустую страницу. `contains()` звёздочки срезает.
- `nameStemmed` + `MATCHES` — это и есть «поиск» в человеческом смысле: стемминг и
  релевантность, «ordinator perks» находит «Ordinator - Perks of Skyrim».
- `categoryName: "Translations"` звучит правильно и для Skyrim SE даёт ноль. Такой
  категории там нет. Переводы ищутся по **`languageName`**.
- `sort: [{random: {seed: N}}]` — настоящий серверный рандом, поэтому «дай любой мод»
  не требует пролистать 139 846 штук.
- Фильтр по `modId` требует числовой `gameId` — слаг не принимается («mod id уникален
  только внутри игры»). Числовой id берётся запросом `game(domainName:)` и кешируется.

### Ради чего всё это: `translations_of()`

Чужой опубликованный перевод — это готовые строки на нужном языке, и для словаря они
стоят больше, чем всё, что может сочинить модель. Отсюда основной запрос:

```python
s = build_search(cfg)
for t in s.translations_of("Ordinator - Perks of Skyrim", language="Russian"):
    print(t.score, t.mod.mod_id, t.mod.name, t.mod.downloads)
```

```
4.00  34345  Ordinator - Perks of Skyrim SE RU                  128120
4.00  73386  Ordinator - Perks of Skyrim - Russian Translation   83684
```

Одного фильтра по языку мало: в той же выдаче лежит «Multiple Enchantments - Ordinator
Patch Rus» — патч, который мод лишь упоминает. Поэтому кандидаты ранжируются по четырём
признакам, и **все они едут вместе с ответом**, а не схлопываются в одно непрозрачное
число:

| Признак | Что значит |
|---|---|
| `name_overlap` | доля значимых слов исходного названия, встретившихся в кандидате |
| `covers_title` | исходное название входит в кандидата подряд и в том же порядке |
| `marked` | кандидат сам объявляет себя переводом (`RU`, `Russian`, `перевод`…) |
| `downloads` | вклад ограничен сверху: популярный патч не должен обойти настоящий перевод |

Слова, которые есть в половине названий (`SE`, `SSE`, `Skyrim`, `Special Edition`,
`patch`, `translation`…), из сравнения выброшены: иначе каждый мод похож на каждый и
overlap перестаёт различать.

Ранжирование — это суждение, а не приговор, поэтому оно вынесено наружу: неверный
порядок можно оспорить, глядя на признаки.

## Translate From Mod

Кто-то уже перевёл этот мод. Его работа — это готовый человеческий перевод ровно тех
записей, на которые мы смотрим, и он бесплатный. Поток:

```
найти донора → скачать → распаковать → прочитать плагины → сопоставить → применить → убрать
```

```bash
POST /api/nexus/transfer/plan    {"mod": "Adamant - A Perk Overhaul", "donor_mod_id": 119747}
POST /api/nexus/transfer/apply   {"plan_id": "...", "status": "needs_review"}
# или всё одним вызовом, включая выбор донора:
POST /api/nexus/transfer/oneshot {"mod": "Adamant - A Perk Overhaul"}
```

`plan` **ничего не пишет**. Решение перезаписать готовую работу принимает человек,
который видит конфликты, а не значение по умолчанию.

### Три вида текста, три вида идентичности

Сопоставления по похожести текста здесь нет и быть не может: у донора текст на целевом
языке, у нас на исходном — сравнивать нечего. Каждое совпадение — это совпадение
идентичности.

**Плагины.** Мод-перевод — это исходный плагин с заменённым текстом: FormID записей те
же, позиции строк те же. Тот же плагин, тот же
`(form_id, rec_type, field_type, field_index)` — значит, та же строка.

Двигается только старший байт FormID — индекс в списке мастеров самого плагина. Внутри
файла он стабилен, поэтому обычно совпадает; сдвигается, только если донор добавил или
убрал мастера. На этот случай есть сопоставление `local_id` по младшим 24 битам — и
только там, где оно однозначно с обеих сторон. Если после маскирования две наши записи
схлопнулись в одну, кандидат уходит в `unmatched`: догадка, записанная в хранилище,
потом неотличима от факта.

**MCM-таблицы** (`interface/translations/<имя>_<язык>.txt`, россыпью или внутри `.bsa`).
Здесь стабилен **не номер строки, а `$КЛЮЧ`** — по нему игра и достаёт текст.
Переводчики свободно переставляют и перекомментируют эти файлы, поэтому сопоставление по
позиции промахивалось бы почти всюду, выглядя при этом работающим. Языковой суффикс
имени отбрасывается, так что `SkyUI_SE_english.txt` и `SkyUI_SE_russian.txt` — одна и та
же таблица.

Упакована таблица или лежит россыпью — **в идентичность не входит**: это способ поставки,
а не строка. У нас «A Matter Of Time» держит таблицу внутри BSA, а опубликованный перевод
отдаёт ту же таблицу файлом; пока контейнер был частью ключа, все 133 строки уходили в
`unmatched` и выглядело это как «донору нечего предложить». Если мод несёт таблицу и так,
и так, выигрывает россыпь — именно её читает игра.

**SWF-интерфейс**, выгруженный FFDec: идентичность — `(имя файла, id символа DefineText)`.
Путь внутри мода у разных загрузок разный, идентификаторы — нет.

**Неочевидное.** Немало русских модов кладут текст в `<имя>_english.txt`, а не в
`_russian.txt` — намеренно, чтобы игра показывала его без смены языка. Сборщик, читающий
только `_russian.txt`, объявит такого донора пустым. Поэтому читаются все языковые файлы,
а решает содержимое — этим и занимается `looks_translated`.

Измерено на настоящих файлах: 241 наша строка SkyUI против 243 донорских — 211 `fill`,
30 `rejected`, 2 `unmatched`. На «A Matter Of Time» после засева ассетных строк — 133 из
133 совпали (`conflict` 117, `same` 16), и выборочная сверка подтвердила, что пары
относятся к одному `$КЛЮЧУ`. Там, где английский и русский расходятся по смыслу
(`'All' → 'Профили'`), это вольность переводчика, а не сбой сопоставления — и ровно
поэтому по умолчанию ставится `needs_review`.

**Ассетные строки нужно сначала засеять.** Долгое время их в хранилище не было вовсе:
`bulk_insert_strings` пересобирает ключ из полей FormID, у строки MCM его нет, поэтому
бутстрап их пропускал, а больше никто не вставлял. На этой сборке это давало 463 461
строку плагинов и ноль ассетных — и области `mcm`/`bsa`/`swf` молча выбирали из пустоты.
Лечится джобом `seed_assets` (`translator/db/asset_seed.py`).

**BSArch требует существующий каталог назначения** — на несуществующий он падает с пустым
stderr, что читается как «в архиве ничего не было». Каталог создаётся заранее.

### Что поток отказывается делать

Опасный случай — донор, который на самом деле не переведён. Часть «переводов» выкладывает
нетронутый английский плагин рядом с переведённым, и его вливание заменило бы настоящий
русский текст исходным, отчитавшись о большом успешном слиянии. Поэтому каждая строка
донора проверяется на символы целевого языка и на совпадение с нашим оригиналом. Строки
без букв (`100%`, `50/50`) проходят: переводить там нечего.

### Исходы

| Действие | Значение |
|---|---|
| `fill` | у нас пусто — чистый выигрыш |
| `conflict` | у нас уже есть другой перевод — это решение |
| `same` | совпадает с нашим, делать нечего |
| `rejected` | строка донора не является переводом |
| `unmatched` | соответствующей записи у нас нет |

По умолчанию `overwrite=false` и `status=needs_review`: донор — это второе мнение, а не
инстанция. Каждая применённая строка помечается `source=nexus-translation`, чтобы чужой
перевод потом не сошёл за наш собственный — ни в отчёте о качестве, ни в обучающей
выборке. Пара «английский оригинал → человеческий перевод» дополнительно уходит в
кросс-модовый словарь: один донор помогает всем модам, где встречается та же фраза.

**Долгий донор — это джоб, а не запрос.** `/transfer/plan` держит HTTP-соединение, пока
донор качается и распаковывается: нормально для архива в 300 КБ и неверно для 300 МБ.
`/transfer/job` кладёт тот же поток в очередь джобов — прогресс идёт тем же SSE, что и у
всех длинных операций, закрытая вкладка ничего не теряет, а запуск виден в Jobs.

Одноразовость — поведение по умолчанию: архив и всё распакованное удаляются, как только
строки извлечены. `keep_archive=true` оставляет архив, если того же донора предстоит
влить в несколько модов.

Распаковываются только плагины, их файлы строк, `.bsa` и `.swf`. Донор нередко весит 400 МБ, из которых
переведённый текст — сорок килобайт; писать остальное на диск, чтобы прочитать мимо, —
расход, который замечают только когда кончается место.

**Имя для поиска донора** берётся не из имени папки: в модлисте она называется так, как
решил сборщик («Adamant» там, где Nexus говорит «Adamant - A Perk Overhaul»), а
ранжирование сравнивает названия. `/api/nexus/donors` сначала разрешает настоящее имя
через `nexus_mod_id` из `meta.ini`.

`auto` на премиумном ключе берёт API, на бесплатном — браузер, а за ним `nxm` как

голый `download_link.json` потратил бы по запросу на файл, чтобы снова получить `403`.

`/api/nexus/account` отдаёт `unattended`: пойдёт ли загрузка без человека. Это поле, на
которое смотрит UI, — оно истинно и для Premium, и для бесплатного ключа с залогиненным
браузером.

`dest_dir` в теле запроса ограничен поддеревом `nexus.download_dir` — иначе любой POST
писал бы файлы куда угодно.

Коды: `401` неверный ключ, `402` нужен Premium, `404` мод/файл отсутствует,
`429` квота, `400` подсказка ни к чему не подошла, `409` браузерный маршрут недоступен
на этом хосте.

Скрытый или снятый модерацией мод отвечает `403 Mod not available`, а не `404` —
измерено. Для вызывающего это та же ситуация, что и удалённый мод, поэтому он
поднимается как `NexusNotFound`: пропустить и идти дальше, а не «что-то не так с
запросом».

## TLS на этой машине

На хосте перехватывается TLS (антивирус/прокси), поэтому без `truststore` любой вызов
API падает с `CERTIFICATE_VERIFY_FAILED`. `web_server.py` и `remote_worker/server.py`
уже делают `truststore.inject_into_ssl()` на старте. Если модуль будет запускаться из
нового entry point (например, команды CLI), инъекцию нужно добавить и туда — в
библиотечном коде её нет намеренно.

## Тесты

`tests/test_nexus_download.py` — 48 тестов, `tests/test_nexus_search.py` — 19,
`tests/test_nexus_transfer.py` — 32, `tests/test_config_edit.py` — 9,
`tests/test_nexus_link_cache.py` — 13. Передача данных проверяется на настоящем
локальном HTTP-сервере, а не на моке: докачка — это переговоры (`Range` туда,
`206` + `Content-Range` обратно), и мок, который всегда отвечает правильно, ничего о
коде разбора этих заголовков не доказывает.

Сам транспорт до Chrome тестами не покрыт: ему нужен браузер и живой аккаунт, поэтому он
проверяется руками. Покрыто то, что может сломаться молча: разбор подписи, отказ принять
ссылку, подписанную для другого мода, цепочка, которая не должна глотать настоящую
ошибку, и решение менеджера о параллельности по флагу `interactive`.
